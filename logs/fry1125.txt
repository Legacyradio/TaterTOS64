  native keycodes directly instead of Linux evdev/XKB keycodes.

why:
  This removes a Linux-only header dependency and makes the path TaterTOS64
  exclusive instead of papering over the missing header. The native keycode
  choice matches TaterTOS input semantics better than evdev because TaterTOS
  currently exposes its own fry_input/TaterWin key ABI, not Linux evdev.
