Fixed liburlpattern strictness failures and TaterTOS Rust Symphonia SIMD codegen failure.

Blocker classification:
- liburlpattern: compiler strictness, not a TaterTOS API gap.
- Symphonia/RustFFT: TaterTOS Rust target/backend SIMD codegen gap, not a
  libc/API gap.

Why:
- third_party/liburlpattern/part.cc, tokenize.cc, and pattern.cc had
  exhaustive enum switches without compiler-visible fallback returns.
- third_party/rust/symphonia_core/v0_6 was compiled with opt-simd-avx,
  opt-simd-neon, opt-simd-sse, and rustfft, which drove rustc/LLVM for
  x86_64-unknown-tatertos into:
  "Do not know how to split the result of this operator!"

Fix:
- Added fallback returns for liburlpattern enum stringify/length helpers.
- Added TaterTOS-only GN feature gates that remove Symphonia/RustFFT SIMD
  features for is_tatertos while keeping codec support enabled through the
  crate's scalar no-SIMD implementation.
