Fixed UI interaction unique identifier subobject-linkage strictness.

Blocker classification:
- compiler strictness, not a TaterTOS API gap.

Why:
- DECLARE_UNIQUE_IDENTIFIER_TYPE uses a static constexpr class-name array.
  That is valid for nested identifier types, but namespace-scope exported
  identifier classes inherited from UniqueIdentifierImpl specializations keyed
  by internal-linkage arrays, which GCC reports as -Wsubobject-linkage.

Fix:
- Added DECLARE_NAMESPACE_UNIQUE_IDENTIFIER_TYPE for namespace-scope identifier
  classes using an inline constexpr class-name array with external linkage.
- Switched ElementIdentifier, CustomElementEventType, UntypedStateIdentifier,
  and InteractiveTestTemporaryIdentifier to the namespace-scope macro.
- Left the original macro intact for nested class identifier declarations.
