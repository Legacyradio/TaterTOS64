Why:
- Static Linux probes were green, but Claude Code requires the dynamic Linux
  runtime path: PT_INTERP, ld-linux, libc .so loading, TLS setup, and Linux
  syscall ABI fidelity.
- The first dynamic boot after staging reached ld-linux but faulted at
  RIP=0x600000014231 with CR2=0xffffffff8183a970.
- Disassembly showed ld-linux loaded a pointer into RDX, called syscall 218
  (set_tid_address), then used RDX immediately after syscall return.
- TaterTOS syscall_entry was clobbering Linux user registers while shuffling into
  the C ABI. Native TaterTOS code tolerated that, but Linux userland expects all
  GPRs except RAX/RCX/R11 to survive syscall.
