What changed:
- Added LGAP.LXE probe (tools/host/lgap.c): exercises nanosleep, fcntl(F_GETFL/F_SETFD),
  dup2, and clock_getres without threading.
- Implemented LNX_clock_nanosleep (230): parses struct timespec from user, computes
  wake time with HPET-based sys_now_ms(), uses existing sched_sleep() for the delay.
  Absolute-time mode (TIMER_ABSTIME) handled.
- Implemented LNX_fcntl (72): supports F_GETFD (1), F_SETFD (2), F_GETFL (3),
  F_SETFL (4) using shared->fd_flags[].
- Implemented LNX_dup (32): finds first empty fd slot, copies fd_ptrs/kind/flags.
- Implemented LNX_dup2 (33): closes target fd if open, copies oldfd to newfd.
- Implemented LNX_clock_getres (229): returns {tv_sec=0, tv_nsec=1000000} (1 ms).
- Updated linux_compat.h with LNX_clock_nanosleep (230).
- Updated build_iso.sh and main.c with LGAP.LXE staging and launch.

Why:
- These syscalls are required by glibc's init path and any real CLI binary
  (Claude Code, Node.js, curl). They were the non-threading gaps remaining after
  the LLIBC probe proved the dynamic libc baseline.
- clock_nanosleep is used by modern glibc (GCC 16.x / glibc 2.40+) instead of
  the older nanosleep(35) syscall. The LLIBC probe didn't hit it because it
  didn't call sleep/nanosleep.
- fcntl is called by glibc init for FD_CLOEXEC setup and by any code that
  manipulates file descriptor flags.
- dup2 is used by shell-like operations and pipe setup.
- clock_getres pairs with clock_gettime and is called by various libc timing
  functions.
