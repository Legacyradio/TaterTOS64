What changed:
- Added Linux epoll/eventfd/timerfd/signalfd syscall handling in
  src/kernel/proc/syscall.c, using the existing TaterTOS fd model underneath.
- Added Linux event translation for epoll_event, including the Linux x86_64
  packed 12-byte epoll_event ABI and FRY_POLL* <-> Linux EPOLL* bit mapping.
- Extended Linux fd read/write/close handling for eventfd, timerfd, signalfd,
  epoll, and inotify-owned objects.
- Added tools/host/lasync.c, a dynamically linked host-built Linux probe for:
  eventfd + epoll readiness, timerfd + epoll readiness, and signalfd4 empty
  nonblocking read.
- Added LASYNC.LXE packaging and marker-gated boot launch through build_iso.sh
  and src/kernel/main.c.

Why:
- Bun/Node/Claude Code rely on Linux async-I/O surfaces. epoll, eventfd,
  timerfd, and signalfd are the next concrete syscall rung after dynamic glibc,
  file-backed mmap, thread clone3, and the syscall gap probe.
- The first boot after adding LASYNC exposed a real timerfd readiness bug:
  timerfd expirations were computed on read(), but epoll readiness checked only
  tm->expirations. That made epoll_wait(timerfd) return 0 after the timer had
  elapsed.
- Fixed that by adding timerfd_update_expirations() and calling it from
  poll_check_fd() and timerfd read paths so epoll and read observe the same
  timer state.
