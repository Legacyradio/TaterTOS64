THE BLOCKER + WHAT WAS JUST DONE (untested)
=====================================================================
The real claude binary is 243 MB. It does NOT fit the boot ramdisk:
- The EFI ramdisk is built by SCANNING the ISO tree, filtered by
  ramdisk_should_load_name() (src/boot/efi_loader.c) — only .FRY/.TOT/.TXT/
  .ICON/.ucode/.ttf/.LXE/.so/.so.{0,1,2,6}/.RUN. (so a real binary MUST be
  named *.LXE to be picked up.) Each file is read CONTIGUOUSLY below 4 GB
  (TATER_BOOT_IDENTITY_LIMIT). A 243 MB contiguous alloc below 4 GB fails
  -> the file is silently skipped. So claude goes on the NVMe, not the
  ramdisk. The kernel already auto-mounts NVMe at /nvme as a SECONDARY when
  a ramdisk root exists (main.c ~444 vfs_mount_secondary) — live boot safe.

But the native ToTFS only supported 128 MB: its block bitmap was a SINGLE
block (32768 bits @ 4 KB blocks). totcopy errored "alloc_blocks_contig:
no free blocks" on the 243 MB file.
