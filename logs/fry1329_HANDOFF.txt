EVIDENCE (serial /tmp/s_fry1327.log):
- claude installs handlers via rt_sigaction, incl. sig 0x1e=30
  (line 423: pid=12 nr=13 rt_sigaction a1=1e). Sig 30 is JSC's
  stop-the-world thread-suspend signal for conservative GC stack scans.
- pid 28 -> tgkill(tgid=12, tid=29, sig=30) returns rc=0, BUT our kernel
  NO-OPS it: rt_sigaction/rt_sigprocmask/sigaltstack just `return 0`
  (syscall.c ~3662) and kill/tgkill never make a signal pending or invoke
  a handler. tid 29 never runs its sig-30 handler, never parks/acks.
- pid 12 and pid 29 then block FOREVER in futex_wait on 0x63ad6e0

ROOT CAUSE: thread-directed signal delivery does not exist. Handlers are
recorded-but-inert; there is no pending-signal state, no frame build, no
rt_sigreturn, no interruptible blocking.

NEXT TASK (#9) — IMPLEMENT REAL SIGNAL DELIVERY (the big one)
=====================================================================
This is the largest remaining linuxulator piece. Suggested build order,
each its own fryN.txt log + boot verify:

1) STATE (process.h / process.c): add per-thread signal state to
   fry_process (or proc_shared where threads share disposition — in Linux
   signal DISPOSITIONS (sigaction) are per-PROCESS/shared across threads;
   the BLOCKED mask and PENDING set are per-THREAD). So:
     - shared: struct { uint64_t handler; uint64_t flags; uint64_t mask;
       uint64_t restorer; } sigact[64];   (dispositions, shared by tgid)
     - per task: uint64_t sig_blocked;  uint64_t sig_pending;
       plus sigaltstack {sp,size,flags} per task.
2) rt_sigaction (nr 13): store/return dispositions into shared->sigact[].
   Honor SA_RESTORER (sa_restorer in a6/act->sa_restorer), SA_SIGINFO,
   SA_RESTART. Return old act. (Currently returns 0 — replace.)
   rt_sigprocmask (nr 14): actually update per-task sig_blocked (SIG_BLOCK/
   UNBLOCK/SETMASK), return old. sigaltstack (nr 131): store per-task.
3) kill/tkill/tgkill (62/200/234): set the bit in the target task's
   sig_pending; if the target is blocked interruptibly (futex_wait etc.)
   and the signal is not blocked, wake it so it returns toward the kernel
   exit path. (tgkill: target = proc_find_task(tid).) Keep the existing
   fatal-default behavior for sigs with NO handler (term/core) — see the
   current tgkill self-kill at syscall.c ~3660 (syscall_exit_current(128+sig)).
4) INTERRUPTIBLE BLOCKING (sched.c sched_block_futex ~515): a blocked task
   with a pending, unblocked, handled signal must stop waiting and return
   -EINTR (futex) so control reaches the syscall-exit path. Add a
   "has deliverable signal" check to the block/wake conditions.
5) DELIVERY on kernel->user return: before returning to user (syscall exit
   and/or IRET in irqdesc/syscall_entry), if the task has a pending,
   unblocked, handled signal:
     - pick lowest signal, clear its pending bit.
     - choose stack: sigaltstack if SA_ONSTACK else current user rsp.
     - build a frame on the user stack: struct rt_sigframe { ucontext_t
       (saved GPRs/RIP/RFLAGS + FPU/xsave), siginfo_t, and a return
       address = sa_restorer (glibc passes one; it does rt_sigreturn) }.
       Match the x86-64 SysV layout EXACTLY (16-byte align; rdi=signo,
       rsi=&siginfo, rdx=&ucontext; rax=0).
     - set RIP=handler, RSP=frame, add signal to blocked mask for the
       handler's duration (plus sa_mask).
6) rt_sigreturn: ADD LNX_rt_sigreturn (nr 15) to linux_compat.h and a
   handler that restores GPRs/RIP/RFLAGS/FPU and the blocked mask from the
   on-stack ucontext, then resumes. (Currently NOT defined at all.)
7) DEFAULT ACTIONS for sigs without a handler: term (most), ignore
   (SIGCHLD/SIGURG/SIGWINCH), core->term. Keep SIGKILL/SIGSTOP unblockable.

WHY sig 30 specifically: JSC suspends each mutator thread by signaling it;
the handler captures the thread's stack bounds/registers and spins on a
futex until the collector resumes it. Without real delivery the collector
waits forever. Once #5+#6 work for sig 30, the GC safepoint completes and
claude should proceed (watch for the next gap or for `--version` output).

GOTCHA for delivery while a thread sits in futex_wait: you must (a) make
the wait return -EINTR (step 4), (b) on the way out deliver the frame
(step 5), (c) the handler runs, parks on JSC's internal futex, (d) the
collector wakes it. Test incrementally — deliver to a self-signal first
(simplest), then thread-directed.

=====================================================================
GOTCHAS (hard-won this session — do not relearn)
=====================================================================
- QEMU IMAGE LOCK: a prior boot (timeout 600) holding out/tater_nvme.img
  makes the next boot die at 0 bytes with "Failed to get write lock". A
  0-byte /tmp/s.log + alive qemu = you're watching a corpse. ALWAYS reap
  qemu before booting and confirm the log grows.
- pkill SELF-KILL: `pkill -f qemu-system` MATCHES YOUR OWN SHELL (the
  command line contains "qemu-system") and kills the launcher. NEVER use
  pkill -f for qemu. Reap by comm instead:
    for p in $(ps -eo pid,comm | awk '$2 ~ /qemu/ {print $1}'); do kill -9 $p; done
  (comm is truncated to 15 chars "qemu-system-x86", which never matches a
  grep/awk pipeline.)
- kprint IS FILTERED: plain kprint() runs through kprint_should_emit()
  (kprint.c ~731) and most lines are DROPPED from serial. Use
  kprint_serial_only() for any beacon you must see. (This is why
  "storage: nvme init" etc never appeared — not lost, filtered.)
- DEMAND PAGING vs RAM: JSC reserves 128 GB VIRTUAL (MAP_NORESERVE); only
  touched pages get physical RAM. Do NOT try to eagerly back it.
- clangd shows a false-positive cascade ('fry_limits.h' not found ->
  FRY_* undeclared). IGNORE — the x86_64-elf-gcc build uses -Isrc/include
  and compiles clean. Trust the gcc build, not clangd.
- smp2: do NOT "simplify" to -smp 1 to get cleaner logs; it changes the
  threading model and hides SMP-specific bugs (this was a corner-cut Zack
  called out). Fix VISIBILITY, never simplify the target config.
