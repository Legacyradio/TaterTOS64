fry1339 - Tater Bridge shared mmap cursor clears claude mmap write fault
timestamp: 2026-06-04 10:34:53 CDT

What changed:
- Moved the Linux mmap top-down allocation cursor from per-thread process state
  into the shared process state:
  - src/kernel/proc/process.h: fry_process_shared.linux_mmap_next
  - src/kernel/proc/process.c: seed shared linux_mmap_next during Linux launch
  - src/kernel/proc/syscall.c: LNX_mmap allocates from shared->linux_mmap_next

Why:
- Linux clone threads share one address space. Keeping linux_mmap_next on each
  thread lets cloned Bun/JSC threads allocate from stale copied cursors and
  overlap existing mappings. The previous boot died on a write-protection fault
  inside a freshly returned anonymous mmap, consistent with an overlapping
  mapping left with older permissions.
