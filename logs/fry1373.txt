fry1373 - rseq, guard pages, and madvise semantics tightened; liveness remains

Date: 2026-06-05 ~14:35 CDT

What changed:
- Added minimal Linux rseq registration state per Tater Bridge thread.
  rseq now records the userspace rseq area and writes cpu_id_start/cpu_id
  plus node_id/mm_cid for the 32-byte ABI used by Claude's glibc path.
- Added trace names for rseq and set_robust_list so worker startup can be
  compared directly against host Linux strace.
- Implemented MADV_GUARD_INSTALL by marking the advised range PROT_NONE and
  removing any present PTEs instead of treating guard stack pages as a no-op.
- Made MADV_DONTNEED region-aware:
    sparse/reserved mappings return without walking every 4K page
    anonymous committed pages are zeroed
    file-private mappings are not zeroed, matching Linux's reload-from-file
    behavior instead of corrupting file-backed contents
- Kept the launcher in final prompt mode:
    claude -p "say hello from TaterTOS in 10 words"

Conclusion:
- The port is still mechanically stable: no exceptions, no unknown syscalls,
  no exit crash, and worker threads register rseq/robust-list successfully.
- The liveness blocker is not basic rseq registration, guard-page no-op
  behavior, or the initial huge sparse MADV_DONTNEED scan.
- The remaining repeated divergence is still the JSC/Bun runtime path:
  only two clone3 workers are created under Tater Bridge, while host Linux
  creates the broader worker set and prints quickly.
- TBSKIP remains suspicious. Final run still has 4 bad pointer slots in the
  same JSC dispatch loop:
    r14=0x3f8 / 0x7f8 -> 0x40000000
    r14=0xff8 / 0xff9 -> 0xffffffffffffffff
