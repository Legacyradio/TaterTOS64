WHY
====
fry1396 proved the numCalleeLocals=0 crash is a deterministic logic bug in a JS
function invoked from an event-loop callback right after socket() returns
-ENOSYS. Serial log (2.1.172 boot, /tmp/s.log) pins the exact failing path:
glibc getaddrinfo on Bun's DNS thread (pid=4):
    openat /etc/nsswitch.conf -> -ENOENT
    openat /etc/host.conf     -> -ENOENT
    openat /etc/resolv.conf   -> -ENOENT
    openat /etc/hosts         -> -ENOENT
    socket(...)               -> -ENOSYS   (twice; nr=41)
The dns-error JS callback is the prime suspect for the empty UnlinkedCodeBlock.
Wiring sockets + resolver files (a) tests that theory decisively and (b) IS the
real networking phase toward an actual API reply — no throwaway probe.

FINDINGS (pre-edit audit, this session)
====
- Native syscall ABI already has a FULL socket suite (syscall.c):
  SYS_SOCKET=72 CONNECT=73 BIND=74 LISTEN=75 ACCEPT=76 SEND=77 RECV=78
  SHUTDOWN_SOCK=79 GETSOCKOPT=80 SETSOCKOPT=81 SENDTO=82 RECVFROM=83
  SENDMSG=108 RECVMSG=109 SOCKETPAIR=120 ACCEPT4=122, wired to the native
  TCP/UDP stack (tcp_connect/tcp_send/tcp_recv/udp_send + sock_udp_rx).
- Linux + native paths SHARE the same fd table (shared->fd_kind/fd_ptrs) and
  FD_SOCKET is ALREADY handled by the shared poll helper (~line 794) and the
  Linux epoll path. Only the Linux dispatch cases are missing.
- linux_compat.h defines ONLY LNX_socket=41 of the socket family.
- Lucky constant overlaps (verified): native O_NONBLOCK=0x800 == Linux;
  SOL_SOCKET=1, SO_REUSEADDR=2, SO_ERROR=4, SO_KEEPALIVE=9, SO_RCVTIMEO=20,
  SO_SNDTIMEO=21, MSG_DONTWAIT=0x40, fry_sockaddr_in layout == Linux
  sockaddr_in, native ACCEPT4 already uses Linux SOCK_NONBLOCK/SOCK_CLOEXEC
  flag values (0x800/0x80000). kernel fry_msghdr layout == Linux msghdr.
- GAPS found:
  * lx_read_fd / lx_write_fd / lx_close_fd do NOT handle FD_SOCKET
    (read/write on a socket would -EBADF; close would LEAK the tcp handle).
    LNX_readv/writev loop over these two helpers, so fixing the helpers
    covers read/write/readv/writev all at once.
  * No native getsockname/getpeername — synthesize from fry_socket fields.
  * tcp_send takes uint16_t len: Linux wrapper must clamp (partial send is
    legal for SOCK_STREAM; callers handle short writes).
  * Native switch lives INSIDE syscall_dispatch() after the is_linux branch
    -> not callable from the Linux dispatcher. Must extract it into
    native_syscall_dispatch(num, a1..a6, cur).
  * EFI ramdisk scanner (efi_loader.c ramdisk_should_load_name) loads only
    .FRY/.TOT/.TXT/.ICON/.ucode/.ttf/.LXE/.so*/.RUN -> /etc/resolv.conf,
    nsswitch.conf, host.conf, hosts would never reach the ramdisk. Scan IS
    recursive from root, so widening the filter (+ staging files in
    build_iso.sh) is sufficient.

PLAN
====
1. linux_compat.h: add LNX_ socket-family syscall numbers (42-55, 288) +
   LNX_SOCK_NONBLOCK/LNX_SOCK_CLOEXEC.
2. syscall.c: extract native switch -> static native_syscall_dispatch(); add
   forward decl above the Linux impl; syscall_dispatch() becomes a thin router.
3. syscall.c Linux dispatcher: add socket-family cases translating Linux ABI
   -> native cases (flag stripping on socket(), addrlen-out on recvfrom/
   accept, getsockname/getpeername synthesized, setsockopt unknown-option
   tolerant, send length clamp).
4. lx_read_fd/lx_write_fd: FD_SOCKET -> delegate to SYS_RECV/SYS_SEND.
   lx_close_fd: FD_SOCKET -> tcp_close + sk->used=0.
5. build_iso.sh: stage /etc/resolv.conf (nameserver 10.0.2.3 = QEMU slirp
   DNS), /etc/hosts, /etc/nsswitch.conf ("hosts: files dns"), /etc/host.conf.
   efi_loader.c: accept ".conf" suffix + exact name "hosts" in ramdisk filter.
6. Clean rebuild (rule 12), restore pristine claude NVMe image, boot KVM
   -smp 1 WITH -device e1000,netdev=n0 -netdev user,id=n0, serial to /tmp/s.log.
7. Compare crash signature vs fry1396 baseline: moved/vanished => socket-error
   callback confirmed as the numLocals=0 function; plus measure how far DNS ->
   TCP -> TLS now gets.
