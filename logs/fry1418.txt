THE FIX (one line + comment, syscall.c ~322)
====
  #define FRY_POLLOUT 0x0002u  ->  0x0004u
  (0x2 is Linux POLLPRI; 0x4 is Linux POLLOUT and ALSO what the OS's own
  user libc fry.h already defined. Epoll translators become identity.)

NEW FRONTIER (same boot, one syscall later)
====
  LXDNS nr=16 ioctl a2=541b rc=-25    <- FIONREAD unimplemented (ENOTTY,
                                         glibc tolerates; optional later)
  LXDNS nr=45 recvfrom a1=11 a2=buf a3=10000 rc=0   <- ZERO?!
  LXDNS nr=3 close                                   <- glibc: empty
- The 51-byte answer IS queued (LXUDP rx + poll POLLIN prove it). The
  native SYS_RECVFROM DGRAM clamp is:
      if (copylen > (uint16_t)a3) copylen = (uint16_t)a3;
  glibc's answer buffer is 65536 (a3=0x10000); (uint16_t)0x10000 == 0
  -> copylen clamped to 0 -> recvfrom returns 0 -> glibc reads an empty
  datagram, closes, retries, same result, EAI_AGAIN.
- SAME truncating clamp at 4 recv sites (recv/recvmsg-iov x2/recvfrom:
  syscall.c 6965/8567/8585/8763). Send sides are safe (LNX wrappers
  clamp len>0xFFFF to a short write before the cast).

FIX (fry1419, in tree at session time): all four sites ->
      if ((uint64_t)copylen > a3) copylen = (uint16_t)a3;
  (if the clamp fires, a3 < copylen <= 0xFFFF so the cast is exact).
