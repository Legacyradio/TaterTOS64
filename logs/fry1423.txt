WHY THE fry1422 DIAGNOSIS IS OVERTURNED
====
Measured per-vCPU host CPU accrual during the fry1423 freeze:
  CPU 0/KVM and CPU 1/KVM each accrue ~2% steadily; iothread 0%.
- A spin deadlock would burn high CPU (even PLE-throttled, asymmetric).
- A dead timer would accrue ~0% (pure HLT, no wakeups).
- ~2%/vCPU on BOTH cores == LAPIC periodic timer FIRING at 1000Hz on
  both CPUs, each tick finding nothing runnable, HLT again.
So the timer interrupt machinery is ALIVE through the "freeze". The
TBFUTEX wait-begin beacon is UNCAPPED for tgid=3 — threads in 10s timed
waits would re-enter (and print) every 10s if wakes fired. 12+ min of
total silence => timed sleepers never wake => now_ms() IS FROZEN while
sched_tick keeps running: the HPET main counter (sole time source for
now_ms/sys_now_ms/poll/futex timeouts) stopped advancing.
A frozen kernel clock also stalls claude internally (its clock_gettime
is HPET-backed; libuv timers + epoll timeouts all dead, event-only
processing alive) — matching pid9's epoll loop going quiet with no
crash and no error in BOTH 1422 and 1423.
KEY CLUE: 'now' went BACKWARD right before the freeze (a TBSCHED line
shows now=77346, then TBFUTEX wait-yield shows now=76478).

CANDIDATE MECHANISMS (next boot discriminates)
====
(a) HPET halted: stray store cleared GEN_CONF.ENABLE (bit 0) — wild
    kernel write into the 0xFED00000 MMIO page.
(b) Stale reads: HPET page lost its UC attribute (e.g. later physmap
    work mapping a huge page over the hole) -> per-CPU CACHED counter
    reads -> frozen, and DIVERGENT per CPU. The backward 77346->76478
    step is exactly two CPUs holding different stale lines.
(c) QEMU HPET quirk. (Least likely; nothing host-side changed.)
fry1422's freeze-at-75.5s + last-line-was-a-timeout-beacon now reads
as: the counter froze near 75571; the final timeout fired at the
boundary (now==wake_time==75571); nothing time-based ever fired again.
Both freezes at guest ~75-77s suggests a time-correlated trigger, not
a pure race — fry1421's identical image ran 900s clean, so it is not
strictly deterministic either. Tracer will tell.
