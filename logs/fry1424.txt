THE TIMING PATTERN (now spanning 4 runs)
====
claude launches ~10s, API connects fire ~13s. Death of all tgid=3
activity: fry1422 ~75.5s, fry1423 ~76.5-77.3s, fry1424 ~73.7s — i.e.
~60s after the request fires. 60s is the standard API request timeout.
fry1421 — the ONE run where TLS completed and 12KB of API response
arrived — sailed past 75s and ran its full window. Hypothesis: TLS
handshake stalls (cause TBD, possibly itself a lost-wakeup hitting the
crypto/verify worker); 60s later the request layer times out; claude
tears down / exits / wedges. The ~75s "freezes" are this, not kernel
death.
