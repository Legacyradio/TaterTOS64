fry1436 — Linuxulator: EPOLLET (edge-triggered epoll) IMPLEMENTED.
ROOT CAUSE OF THE STALL FAMILY, NAMED BY fry1435: Bun (claude's
runtime) registers its event-loop wakeup eventfds with EPOLLIN|EPOLLET
(LXEPCTL events=80000001, fds 7 and 16) and NEVER reads the counter —
which is CORRECT under edge semantics, where each write yields exactly
one wakeup. Our epoll was purely level-triggered and silently dropped
the ET bit in lx_epoll_to_fry, so once a wakeup counter went nonzero it
was re-reported on EVERY epoll_pwait2 — fry1435 measured the same
eventfd (fd 16, counter frozen at 4) delivered as a ready event
12,032+ times. Bun's loop spun on the phantom wakeup instead of
parking, and the next phase of work (session init, new connections)
never ran. This is the mechanism behind the fry1419..1433 stall masks.

CHANGES — all in src/kernel/proc/syscall.c (rule 6 whys inline)
------------------------------------------------------------------------
1. #define LX_EPOLLET 0x80000000u (was undefined — the bit vanished in
   mask translation, which is why no code path could ever see it).
2. struct epoll_item: + et / et_valid / et_token. Token = the fd's
   kind-specific readiness state at last report; unchanged token ==
   same edge == suppressed.
3. epoll_ctl ADD and MOD: capture ET bit; both reset et_valid (MOD
   re-arms edge reporting, matching Linux).
4. epoll_et_token(): FD_EVENTFD -> counter value; FD_TIMERFD ->
   expirations. Both are natural edge counters: every eventfd write
   changes the counter, so each write re-arms exactly one report, and
   coalesced writes between polls collapse to one wakeup — Linux
   behavior. Other kinds: no token -> LEVEL fallback + one-shot
   "LXEPET WARN" serial beacon, so an ET registration on an
   unsupported kind can never become an invisible spin again. (Scoped
   honestly: sockets/pipes would need monotonic arrival counters
   plumbed through netcore; nothing registers them ET today, and the
   fallback is the pre-fry1436 status quo, made loud.)
5. Wait loop: ET items with unchanged token are suppressed before the
   ready-list fill; when readiness drops to zero the item re-arms
   (covers read-then-rewrite of the same counter value).
