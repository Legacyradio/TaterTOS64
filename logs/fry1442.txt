CHANGES (rule 6 whys)
------------------------------------------------------------------------
1. tools/totcopy.c — new "--mkdir <path>" mode (do_mkdir): allocates a
   DIR inode + one data block with "." / ".." dirents, mirroring
   mktotfs's root layout; adds the entry to the parent. WHY: totcopy
   had no way to create directories, and /nvme/.claude must exist
   before first boot so .credentials.json is readable for auth.
   (Compile-verified host-side. Usage text still lists the old modes;
   --get and --mkdir are both functional via main().)
2. build_iso.sh STAGE_CLAUDE block — stages
     /.claude.json            (from out/etc/clauth/dot-claude.json)
     /.claude/.credentials.json (after --mkdir /.claude)
   onto the NVMe ToTFS image. Same strip-before-push rule as the ESP
   copies (fry1409). Warns loudly if clauth files are absent.
3. src/kernel/main.c bridge env — HOME=/nvme, TMPDIR=/nvme (was
   HOME=/, TMPDIR=/tmp, both on the RO ramdisk where mkdir = EIO,
   fry1441). TMPDIR=/nvme rather than /nvme/tmp so claude's own
   "mkdir $TMPDIR/claude-0" has an existing parent.

EXPECTED EFFECT
------------------------------------------------------------------------
claude's CLI bootstrap can create /nvme/.claude/debug, /nvme/claude-0,
and its transcript dirs. The emitter comes up, and the TBWRDATA beacon
(fry1440) mirrors the debug-file text to serial while stream-json
events flow to stdout -> kprint_write -> serial. If output appears:
DONE — read the result event. If the emitter still fails, the debug
log text (now writable) names the next blocker from inside claude.
