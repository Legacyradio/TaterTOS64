Cause found by code audit: totfs_alloc_block() in the KERNEL caps its
scan at one bitmap block (TOTFS_BLOCK_SIZE*8 = 32,768 blocks = 128 MB)
and struct totfs_fs caches only ONE bitmap block. The staged 248 MB
RCLAUDE.LXE occupies ~60,700 blocks — the entire sub-128MB region is
full, so the allocator never finds a free bit and every create/mkdir
returns EIO. The HOST tools (mktotfs/totcopy) already handle
multi-block bitmaps (the on-disk format is correct; 400 MB image = 4
bitmap blocks, sb.block_bitmap_blocks=4) — only the kernel was capped.
Config rewrite worked because it reused the file's EXISTING blocks.
