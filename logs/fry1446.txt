src/kernel/proc/syscall.c dispatch:
- rmdir -> unlinkat(AT_FDCWD, path, AT_REMOVEDIR) — real routing, the
  native handler already supports AT_REMOVEDIR.
- fsync/fdatasync -> 0: totfs_write_block writes through synchronously,
  there is no dirty cache to flush; success is the truthful answer.
- chmod/fchmod/fchmodat/chown/fchown/lchown/utimensat -> 0 (no-op
  success): ToTFS v1 has no permission/owner/timestamp model — the
  native mkdirat already documents "ignores mode". Returning ENOSYS
  made claude's atomic-write machinery abort; no-op success matches
  the filesystem's actual contract.
- symlink/symlinkat -> -EPERM: ToTFS cannot represent symlinks. EPERM
  is Linux's documented answer for "filesystem does not support" —
  ENOSYS would advertise a kernel gap and invite retry loops.
