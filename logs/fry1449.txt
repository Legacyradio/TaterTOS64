rename(82), renameat(264), renameat2(316).

src/kernel/proc/syscall.c dispatch:
- rename -> SYS_RENAMEAT(AT_FDCWD, old, AT_FDCWD, new); renameat ->
  passthrough; renameat2 -> same when flags==0, else -EINVAL
  (RENAME_NOREPLACE etc. unsupported — honest EINVAL, not silent
  ignore). WHY: claude's atomic writes end in rename(tmp, final);
  ENOSYS forced the "fallback to non-atomic write" path seen in its
  own debug log. Native SYS_RENAMEAT (case 117) already does the work
  via vfs_rename/totfs_rename_vfs.
- ftruncate -> native SYS_FTRUNCATE (case 89; FD_FILE + FD_MEMFD).
- SYS_MKDIRAT: before vfs_mkdir, stat the PARENT — missing parent now
  returns -ENOENT (recursive mkdir's signal to create ancestors),
  non-dir parent returns -ENOTDIR. WHY: the blanket -EIO made claude's
  mkdir-recursive abort instead of recursing — the exact transcript
  failure "EIO mkdir /nvme/.claude/projects/-" (fry1447/1448).
  Mount-root parents verified statable (fry1443's EEXIST on /nvme came
  from the existing vfs_stat(path) check).
