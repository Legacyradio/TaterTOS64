IMPLEMENTATION CAUTION
------------------------------------------------------------------------
The source audit shows clone3 thread support exists, but execve is not
currently implemented in the Linux syscall translator. So a real
posix_spawn path is probably not "just vfork"; it likely requires a
vfork/fork child path plus execve/execveat support, or a deliberate
spawn shortcut that launches a new Linux process from the requested path
without pretending full fork semantics exist.

Next engineering step should be an exec/spawn design cut, not blind
patching:
  1. Instrument or inspect the vfork/posix_spawn path enough to confirm
     whether execve(59) follows immediately after vfork once vfork stops
     returning ENOSYS.
  2. Implement the narrowest honest process-spawn path that supports
     Claude Code's helper launches, preserving existing clone3 thread
     behavior.
  3. Verify with a boot that the posix_spawn errors disappear or move to
     the next named syscall.
