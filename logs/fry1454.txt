fry1454 - Selftest VM-region constant fixed; long q35 -smp 4 boot on FS22
vars proves vfork remains the subprocess blocker.
Date: 2026-06-13. Author: Codex.
========================================================================

SUMMARY
========================================================================
Corrected a stale selftest expectation and reran the Claude Code boot using
the user's FS22 flash-drive OVMF vars file, q35 machine profile, -smp 4,
and a long timeout.

The boot reached Claude Code again. Networking and NVMe were good. The
process exited with the known auth 401 state, and the subprocess frontier
is now confirmed: posix_spawn still fails at unimplemented vfork(58).


WHAT CHANGED
========================================================================
File changed:

  src/kernel/selftest.c

Fix:

  - Updated the FRY_VMREG_MAX selftest expectation from 256 to 2048.

Why:

  src/include/fry_limits.h already documents FRY_VMREG_MAX = 2048 from the
  earlier fry1390 VM-region expansion. The selftest still expected the old
  256 value and panicked before Claude could boot:

    SELFTEST FAIL: FRY_VMREG_MAX got=0x800 want=0x100


QEMU COMMAND CORRECTION
========================================================================
The first retry used the user's FS22 vars file but missed the known-good
q35 machine profile. That boot saw zero PCI devices, no e1000, no NVMe, and
then hit the stale selftest panic.

Corrected command:

  timeout 1200s qemu-system-x86_64 \
    -m 4G -machine q35,accel=kvm -cpu host -smp 4 \
    -drive if=pflash,format=raw,readonly=on,file=/usr/share/edk2/x64/OVMF_CODE.4m.fd \
    -drive if=pflash,format=raw,file=/mnt/usb115/TaterTOS_claude_milestone_2026-06-12/OVMF_VARS_copy.fd \
    -cdrom out/tatertos64v3.iso \
    -drive file=out/tater_nvme.img,if=none,id=nvme0,format=raw \
    -device nvme,drive=nvme0,serial=tatertos-nvme \
    -netdev user,id=n0 -device e1000,netdev=n0 \
    -display none \
    -serial file:/mnt/usb115/TaterTOS_claude_milestone_2026-06-12/s_fry1453_q35.log
