WHAT CHANGED (no shortcut; mirrors existing thread-join lifecycle)
------------------------------------------------------------------------
1. src/kernel/proc/process.c — new process_wait4(pid, *status_out, nohang):
   - Targets a child PROCESS leader (pid==tgid), not a sibling thread.
   - An exited process is already left PROC_DEAD by proc_free with
     exit_code preserved and the slot retained until proc_alloc reuses
     it, so a dead child is collectable. No change to the universal exit
     path was needed (the existing PROC_DEAD+exit_code IS the zombie).
   - PROC_ZOMBIE -> encode status, proc_free, return pid.
   - PROC_DEAD   -> encode status, mark slot UNUSED (final reap, no
     double-collect), return pid.
   - alive + nohang -> return 0 (no status write).
   - alive + blocking -> sched_block/sched_yield/recheck loop, modeled on
     process_thread_join.
   - status encoding: ((exit_code & 0xff) << 8)  [wait(2) normal-exit].
   - Returns -ECHILD for no-such-pid / pid-is-a-thread.
2. src/kernel/proc/process.h — prototype.
3. src/kernel/proc/syscall.c — case LNX_wait4 (nr 61):
   wait4(pid,*wstatus,options,*rusage). nohang = options & 1 (WNOHANG).
   pid>0 -> process_wait4; pid<=0 -> -ECHILD (any-child/pgrp waits need
   parent->child tracking we don't keep yet; posix_spawn reaps a specific
   pid, so this covers the tools path). Writes *wstatus (user_buf_writable
   guarded), zeroes rusage(144B) if provided. TBWAIT4 trace beacon for the
   claude tgid.

NEW BLOCKER EXPOSED (next step — NOT this step's scope)
------------------------------------------------------------------------
The execve'd child subprocess spawns and is now reaped, but ABORTS before
doing useful work. status 0x8600 = exit 134 = 128+SIGABRT. Trace of the
child (pid 20):
    TBVFORK parent=5 child=20
    nr=13 rt_sigaction rc=-22 (EINVAL)
    nr=9  mmap        rc=-12 (ENOMEM)   <-- child AS can't map memory
    fd=2 writes "*** stack smashing detected ***: terminated"
    TBSIG default-exit target=20 sig=6  (SIGABRT)
Root area: the child's post-execve address space is not fully set up —
anonymous mmap returns ENOMEM and the stack canary (__stack_chk_fail)
trips. This is the "separate AS on exec" half of child lifecycle. wait4
was necessary but the child needs a working AS to actually run a tool.
