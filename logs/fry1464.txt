ROOT CAUSE (the fry1463 child SIGABRT)
------------------------------------------------------------------------
LNX_vfork did:  sched_add(child); sched_yield(); return child->pid;
That is NOT vfork. A vfork child runs in the PARENT's address space on
the PARENT's stack (child rsp = parent rsp) until it execve's/exits. Real
vfork SUSPENDS the parent for that window. Ours only yielded once, then
the parent resumed and ran CONCURRENTLY with the child on the shared
stack -> __stack_chk_fail ("stack smashing detected") -> SIGABRT (exit
134). The fry1463 rt_sigaction EINVAL (correct: EINVAL on SIGKILL/SIGSTOP)
and mmap ENOMEM (abort handler) were downstream noise, not the cause.

FIX (mirrors existing process_thread_join wait-loop; no shortcut)
------------------------------------------------------------------------
1. src/kernel/proc/process.c:
   - process_vfork_child_active(pid): 1 while child alive AND still
     linux_vfork_child (pre-exec); 0 once it execs (flag cleared) or exits
     (slot DEAD/UNUSED).
   - process_wake_pid_waiters(pid): wake PROC_WAITING procs with
     wait_pid==pid (execve uses it; child exit already wakes via proc_free).
2. src/kernel/proc/process.h: prototypes.
3. src/kernel/proc/syscall.c LNX_vfork: after sched_add(child), block the
   parent in a recheck loop (wait_pid=child_pid; sched_block; sched_yield;
   refetch cur) until process_vfork_child_active(child_pid)==0.
4. src/kernel/proc/syscall.c lx_execve_current: after lx_write_cr3(new_cr3)
   (child now on its OWN address space), if was_vfork_child ->
   process_wake_pid_waiters(cur->pid) so the parent resumes safely on the
   old (its) address space. was_vfork_child already prevents destroying
   old_cr3, and shared_release skips AS-destroy for a vfork child that
   exits pre-exec, so the parent's AS is intact either way.
