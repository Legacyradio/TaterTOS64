fry1467 - stdio redirect override: fds 0-2 now support a dup2'd pipe/file
override (with console/EOF fallback). Advances spawn EBADF -> EINVAL; main
inference UNREGRESSED. Next: rt_sigaction EINVAL in the spawn child.
Date: 2026-06-13. Author: Claude (Opus 4.8).
========================================================================

WHY
------------------------------------------------------------------------
fry1466 left the spawn at dup2 EBADF. Root: fds 0-2 were modeled as the
implicit kernel console with NO table entry, and:
- dup2 explicitly rejected newfd<3 (return -EBADF) — but dup2(pipe/file,
  0/1/2) is THE posix_spawn stdio-redirect operation.
- fd_install / fd_release guarded fd<3 (couldn't store an override).
- lx_write_fd sent fd 1/2 UNCONDITIONALLY to console (ignored overrides);
  lx_read_fd treated fd 0 as always-EOF; lx_close_fd no-op'd 0-2.

WHAT CHANGED (override-with-fallback; default path byte-identical)
------------------------------------------------------------------------
src/kernel/proc/syscall.c:
- fd_install / fd_release: guard fd<0 (allow 0-2 entries).
- LNX_dup2: removed the "newfd<3 -> EBADF" rejection (fd_install + the
  close-before-install via lx_close_fd now handle 0-2).
- lx_write_fd: fd 1/2 -> console ONLY when no override entry; else fall
  through to the table dispatch (pipe/file/socket write).
- lx_read_fd: fd 0 -> EOF ONLY when no override; else table dispatch.
- lx_close_fd: 0-2 no-op ONLY when no override; else real close +
  fd_release (reverts fd to implicit console).
Principle: when nothing is dup2'd onto 0-2 (the normal case, incl. the
main claude process), behaviour is exactly as before -> no regression to
claude's own stdout/serial result path.
