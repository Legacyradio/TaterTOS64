BACKGROUND
------------------------------------------------------------------------
rg's child spawn fails with "ENFILE: file table overflow, posix_spawn
'rg'" (Bun). The ENFILE count is INVARIANT at 2 across:

- FRY_FD_MAX  64 -> 256 (fry1478): booted fine, no change to ENFILE.
So neither the socket pool nor the per-process fd table is the limit.
Remaining socketpair-path pool not yet touched: PIPES (each AF_UNIX
socketpair = 2 g_pipes).

ATTEMPT (reverted)
------------------------------------------------------------------------
FRY_PIPE_MAX 128 -> 256. RESULT: kernel HALTS at early boot (serial stops
right after "DHCP:OK"/kernel-entry "K", ~1 KB, QEMU exits 0). fry1478 with
the same FD_MAX=256 booted fully, so the pipe bump is what broke boot
(g_pipes[] is only +528KB at 4KB/pipe, so likely a BSS/layout boundary,
not raw size — NOT chased). Reverted FRY_PIPE_MAX -> 128 to restore boot.

KEPT: TBSPAIR beacon in the LNX_socketpair handler (syscall.c) logging
pipes_used/FRY_PIPE_MAX and socks_used/FRY_SOCK_MAX at every socketpair
call (cap 60). This measures whether pipes actually starve at the rg
spawn, and whether usage climbs monotonically (LEAK) vs plateaus (genuine
need) — the right diagnostic before bumping pools blindly again.
