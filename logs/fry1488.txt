=== THE REAL ROOT CAUSE (code-confirmed, not grep) ===
claude's Grep tool runs ripgrep in "embedded" mode = it re-execs its OWN 250 MB binary (RCLAUDE.LXE) as `rg`. It does this via vfork+execve. Our kernel:
 - LNX_vfork SUSPENDS the calling thread until the child execve's or exits.
 - lx_execve_current (syscall.c:5128): elf_load_linux (:5140) EAGER-loads the whole 250 MB image, THEN wakes the vfork parent (:5220). The loader (linux_elf.c:343-377) pmm_alloc_page + streams each segment from the file. No COW/shared-page/refcount exists in the VMM (verified absent).
 => The rg self-re-exec's execve takes longer than the whole run to finish; the vfork parent (claude main, pid 5) is suspended the entire time; claude never reaches session init. At 16 slots rg's spawn fails first (socketpair ENFILE/EBADF), so the self-re-exec never happens and claude completes (degraded: no Grep).
