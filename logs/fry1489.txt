=== WHAT WAS WRONG WITH THE PASTED ONE-LINE FIX ===
Copying only read-only segments from the already-resident parent image is real but incomplete.
It avoids re-streaming the first two RCLAUDE.LXE PT_LOAD segments, but the big writable/data
segment at va=0x60ed9a0, file=0x8fe7660 still streams from disk and the vfork parent remains
suspended. Copying the writable segment directly from the live parent would be semantically
wrong because .data may already be mutated.

=== FIX IMPLEMENTED ===
src/kernel/proc/linux_elf.c:
- Added a streamed-segment cache for large Linux ELF PT_LOAD bytes.
- During the first streamed load of RCLAUDE.LXE, the loader still reads from disk into the
  process image, but also copies those exact clean file bytes into kernel-owned cache pages.
- Later self-reexecs copy clean cached bytes into newly allocated destination pages. This
  includes the writable/data segment without copying mutated live .data from the parent.
- Existing read-only parent-image reuse remains as a fast path for RO segments.

src/kernel/proc/linux_compat.h, src/kernel/proc/process.c, src/kernel/proc/syscall.c:
- Extended elf_load_linux with optional self-reexec reuse context.
- Normal launches pass no reuse context.
- execve passes reuse context only for vfork children re-execing the same stored process path.

src/include/fry_limits.h and src/kernel/selftest.c:
- FRY_SOCK_MAX is now 32 so rg/Grep's posix_spawn can proceed instead of failing early at 16.
- Selftest assertion updated to 32.
- Stale comment about the old "worker deadlock" theory was replaced with the loader-cache
  explanation.
