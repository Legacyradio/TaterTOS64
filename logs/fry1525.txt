Root cause found (the real blocker for C):
  src/kernel/proc/syscall.c lx_write_fd, fd 1/2 branch (~line 4845): a Linux child's
  stdout/stderr WITHOUT a redirect override is sent to kprint_write() - the kernel
  FRAMEBUFFER CONSOLE - NOT to the process outbuf that the Shell pump
  (SYS_PROC_OUTPUT) drains. So Claude's 935-byte UI went to the fb console; the
  Shell drained an EMPTY outbuf and the C1 parser had no bytes to render. The garble
  seen in earlier runs (fry1520c) was the raw fb console, a layer SEPARATE from the
  Shell window - not the Shell terminal at all.

Correction to an earlier assumption:
  fry1523/1524 noted "the master pump already exists." Half-right: the INPUT side
  (keyboard -> inbuf -> child, completed by the fd0 fix) existed, but the OUTPUT side
  was never connected - the child writes to the fb console, not the outbuf the pump
  reads. Wiring child fd1/2 -> outbuf is the user's E "master pump" output half and
  the genuine prerequisite for C, exactly as the user originally sequenced.
