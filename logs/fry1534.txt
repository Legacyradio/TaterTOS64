Diagnosis: Claude's stdin bytes are read (likely by a libuv threadpool reader, since

  write to the loop's async pipe/eventfd -> main-loop epoll wake) is not firing - no
  async/eventfd/epoll activity accompanies the reads. So the byte is consumed but
  the keypress is never dispatched to the Ink prompt -> UI frozen at the prompt.
  This is the event-loop/missed-wakeup family seen before (futex wake-miss, timerfd
  spin). NOT a focus problem, NOT the menu key mapping, NOT the fry1531/1533 totfs

  keypress path) here does not - consistent with a racy/unreliable async wakeup.
