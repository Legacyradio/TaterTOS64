CONCLUSION / BISECT (per fry1540 open question)
---------------------------------------------------------------------------------
The SYS_PROC_INPUT beacon fired for the Shell process during the main-UI phase.

This indicates:
- Keystrokes are reaching the Shell (compositor → Shell path is live).
- The forward via fry_proc_input to SYS_PROC_INPUT is executing for Shell.

No beacon observed for Claude pid=14 before the crash sequence.
However, the Claude TUI was visible and had rendered content + prompt area (screenshot 1), showing that some input path to Claude had previously succeeded enough for the app to reach main UI.

The crash is the pre-existing network-subprocess teardown issue (user-space page faults in Claude pid=14 during socket cleanup on subprocess exit, escalating to unhandled kernel page fault on pid=14 exit). This matches the top open blocker documented in HANDOFF_claude_interactive_2026-06-15.md (triple fault on real network I/O + kill of helper).

The beacon achieved its purpose: visibility into the delivery syscall. Input delivery to Shell is functioning; the observed failure mode in this run is the teardown bug (not a pure "no data reaches SYS_PROC_INPUT for Claude" in the input path itself).

The instrumentation step (fry1541) is complete.
