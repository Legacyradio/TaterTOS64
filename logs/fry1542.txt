---------------------------------------------------------------------------------
RESULTS / CONCLUSION
---------------------------------------------------------------------------------
The kernel page fault is inside the TCP teardown path for real network sockets belonging to an exiting process (Claude pid=14 / its threads).

Precise trigger sequence (from serial + source):
1. Claude in main UI performs network I/O (real TCP to API).
2. Kills helper subprocess → many live TCP fds in the process group.
3. Exit path (proc_free / shared_release) walks fds, hits the SOCK_STREAM case for each, calls tcp_close(handle).
4. tcp_close does the minimal range check then direct &tcp_conns[conn] + conditional send_segment on c->state / c->fields.
5. One or more of: stale handle (already closed by network stack or prior path), c in inconsistent state (active=0 but struct not zeroed, bad pointers in tx/rx rings, etc.), or concurrent modification during multi-threaded exit + kill.
6. Dereference inside tcp_send_segment (or called code) produces kernel page fault at the observed RIP/CR2.
7. Unhandled → panic + reset.

Collateral user faults (repeated vec=14/sig=11 inside Claude at 0x293cb7c) are symptoms: the app's runtime receives bad socket state/errors during the request, leading to its own page faults before the host teardown even completes.

This is 100% consistent with the handoff diagnosis ("first exercised now that Claude opens REAL TCP sockets", "tcp_close UAF/bad-handle when many sockets close at once on a killed proc", "socket refs double-free", "AF_UNIX g_pipes refcount" — though here it's the non-unix branch).

The fry1541 beacon succeeded in its narrow goal (visibility at SYS_PROC_INPUT) but the verify run was cut short by this pre-existing blocker. Input delivery to Shell was confirmed working; Claude itself never got a clean TBPROCIN in the trace because the app crashed before full roundtrip.

No assumptions: all conclusions tied directly to serial lines + exact source locations in current tree. Reproducible on any run that gets Claude far enough to open + close real TCP sockets + kill a subprocess.

OPEN ITEMS (for debate)

- Harden the tcp_close path and all callsites (range + active check before any c-> access; zero on alloc; refcounting on tcp_conns themselves?).
- Make socket teardown in shared_release safe for bulk/abrupt close (e.g. mark sockets "zombie" first, drain, or use a separate close queue).
- Distinguish real TCP vs AF_UNIX handling more explicitly (the unix branch already has extra g_pipes refcount logic; the stream branch jumps straight to tcp_close).
- Whether the kill of the helper (SIGTERM etc.) should force socket shutdown before fd close.
- Any locking needed around tcp_conns during process exit (current code has no obvious lock in this path).
- Repro with targeted logging (e.g. beacon every tcp_close call with the pid).
