---------------------------------------------------------------------------------
WHY / METHOD (Rule 6) — TCP ownership (core) + input pass-through (to drive the test case)
---------------------------------------------------------------------------------
Observed in fry1541 beacon run + serial: when Claude (real TCP sockets to API + spawns/kills helper) exits or kills subprocess, proc_free -> shared_release walks fds, hits SOCK_STREAM case, calls tcp_close on handles. This exercised the teardown path first time with real net conns, leading to UAF/bad-handle/double-close in tcp_close (and callers), kernel page fault in teardown, full panic/reset.

tcp_conns[] had no ownership model — only sk->refs on the fry_socket side, direct calls to tcp_close when last sk ref, no protection on the conn side. tcp_close did minimal range check then direct c = &tcp_conns[conn] + state/send without checking active/refs or handling bulk close on killed proc.

Fix: explicit refs on struct tcp_conn.
- Init refs=1 on alloc (tcp_connect/tcp_listen) — the creating socket owns it.
- tcp_conn_retain on acquire (allocation, accept paths, etc.).
- tcp_conn_release (dec; only when ==0 do the real close logic + zero slot).
- tcp_close now delegates to release (thin public "I no longer need this handle").
- Harden accessors (is_connected, get_state, rx_available) to treat !active || refs==0 as closed.
- Update all teardown/close sites (process.c shared_release, syscall.c SYS_CLOSE/lx_close/dup2/etc.) to call via tcp_close (now safe) and clear handles.
- WHY: central ownership on conn side; last owner does real close; safe against bulk/abrupt close on killed proc with many real TCP (Claude case); prevents the observed UAF/panic. Matches prior resource patterns (g_pipes refs, SPCEN census, locked exits).

Separately, to drive the test (type prompt in Claude TUI in main UI/alt-screen/raw takeover so it does network + kills helper + hits the teardown we just fixed):
- Input delivery (compositor TW_MSG_KEY_EVENT -> Shell process_input_stream -> fry_proc_input -> SYS_PROC_INPUT -> child's inbuf + wake) was the open from handoff/fry1540/1541.
- TBPROCIN beacon (added prior) showed partial: some to RCLAUDE pid, but lots of controls (0x04/0a/11) still to Shell pid=13; Enter not reliably reaching child in takeover.
- Shell still consuming; pass-through incomplete when caller used 0 or term_child_pid not honored.

Fixes in shell.c process_input_stream:
- Relaxed "ascii !=0" gate for children (forward on PRESSED even ascii=0).
- Standardize Enter (0/\n/\r) to \r for child (standard terminal submit).
- Force target = forward_pid ? forward_pid : term_child_pid (catch all paths when child has terminal).
- WHY: when term_child_pid set (alt-screen child), Shell must be pure pass-through; no local consumption; all pressed keys (incl. ascii=0/specials) to child; Enter as \r so TUI accepts submit. Matches handoff note on chain stopping in alt-screen/raw. (Earlier incremental fixes for GUI child fd0/epoll/inbuf/wake were prerequisites.)

Evidence captured via guest serial (/tmp/serial.log) + beacons + app traces (QEMU -D was empty/useless for input path with guest_errors).

CHANGES (with locations + WHY in code/comments)
---------------------------------------------------------------------------------
netcore.c:
- struct tcp_conn: added uint32_t refs;
- tcp_connect: after active=1: c->refs = 1;
- tcp_listen: after active=1: c->refs = 1;
- Added static inline tcp_conn_retain / tcp_conn_release (dec only acts on ==0; real close logic moved here).
- tcp_close: now just calls tcp_conn_release (comment: "delegates to refcounted release").
- tcp_is_connected / get_state / rx_available: check !active || refs==0.
- WHY: see above.

process.c (shared_release, called from proc_free on exit of pid with real TCP):
- In FD_SOCKET SOCK_STREAM else: call tcp_close on handles (with comment: "Use tcp_close (now refcounted release) ... prevents UAF... See netcore.c tcp_conn_release").
- WHY: the teardown site that was crashing.

syscall.c (multiple close paths: SYS_CLOSE, lx_close, dup2 close of socket fds, etc. — all had parallel "if domain==1 ... else if SOCK_STREAM tcp_close" logic):
- Added comments in each: "Use tcp_close (now refcounted release). WHY for fry1543: central ownership... prevents the teardown UAF...".
- Calls unchanged (now safe via the delegation).
- WHY: every place that drops a TCP handle on close must go through the owned release.

shell.c (process_input_stream — the terminal emulation for child):
- TW_MSG_KEY_EVENT: relaxed to if (PRESSED), target = forward_pid ? forward_pid : term_child_pid, if (target) { if (c==0||\n||\r) c='\r'; fry_proc_input(target, &c, 1); } else if (ascii!=0) handle...
- Raw byte fallback: similarly force target and map Enter to \r.
- Comments with full WHY (previous gates caused Shell consumption in takeover; force ensures pass-through; map for TUI submit).
- WHY: to let user drive prompt + Enter in Claude TUI so network + helper kill exercises the TCP teardown we fixed.

All changes have WHY in code/comments for the log.
