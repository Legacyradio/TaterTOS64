---------------------------------------------------------------------------------
WHY (Rule 6)
---------------------------------------------------------------------------------
fry1547 found the TUI "can't type" is NOT an OS input-delivery bug: keystrokes ARE delivered to Claude's stdin inbuf (126x nw=1), but Claude's main thread is wedged in an openat/futex storm spawning/connecting MCP servers + reading /proc/self/stat (ENOENT), so it never returns to the loop that reads fd 0.

While reading build_iso.sh I found the staging hook does NOT merely copy the config: at build_iso.sh:191-212 (gated TBRIDGE_FAST_AGENT_BUS=1, default 1) a python step INJECTS an `agent-bus` MCP server into the staged dot-claude.json:
    mcpServers.agent-bus = { type: stdio, command: /usr/bin/tbridge-agent-bus, args: [], env: {PYTHONUNBUFFERED, PYTHONDONTWRITEBYTECODE} }
The real ~/.claude.json has exactly one top-level MCP server (agent-bus); the hook normalizes it to the TaterTOS tbridge binary. This matches the serial: "mcp-logs-agent-bus" churn + child pid=41 loading librt = Claude bringing up that agent-bus server.

To TEST whether MCP spawn/connect churn is the wedge, the staged config must have NO MCP servers, so Claude goes straight to the interactive loop. Done as a GATED toggle so default builds are byte-for-byte unchanged.
