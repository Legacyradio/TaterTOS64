# fry1634 — QEMU boot fix: skip chrome_probe + GUI, launch shell directly
Date: 2026-06-17 ~17:35 CDT
Type: boot fix (Hermes port integration)
Author: planv3 Rules 1/5/6/75

---------------------------------------------------------------------------------
OBJECTIVE
---------------------------------------------------------------------------------
Fix QEMU boot so the TaterTOS shell appears and is interactive.
Two issues discovered during integration testing:

1. chrome_probe hangs after NVMe size bump (1024→2048 MB)
2. GUI spawns and blocks init's shell fallback loop (fry_wait never returns)

---------------------------------------------------------------------------------
CHANGES
---------------------------------------------------------------------------------

src/user/init/init.c:
  - Replaced chrome_probe launch block (lines 98-110) with skip message
  - Replaced GUI launch block (lines 100-117) with no-op (pid=-1, gui_failures=3)
  - Shell now launches immediately after smoketest
  - Log: "init: skipping chrome_probe (fry1631: NVMe size bump)"

build_iso.sh:
  - NVME_SIZE_MB: 1024 → 2048 (for 217 MB sysroot)
  - Fixed STAGE_CLAUDE unbound variable: ${STAGE_CLAUDE:-0}
  - Added stage_hermes.sh source call before ISO creation
  - Shell copied to /apps/SHELL.TOT on NVMe (init loads this first)

stage_hermes.sh (NEW):
  - Creates /apps directory on ToTFS
  - Copies shell.tot → /apps/SHELL.TOT
  - Copies python3.fry → /apps/python3.fry
  - Stages Python stdlib (2,410 files) to /usr/local/lib/python3.14/
  - Stages site-packages (22 pure Python deps)
  - Stages Hermes Agent (669 .py files) to /opt/hermes-agent/
  - Uses || true on all totfs_copy_tree calls for resilience

Makefile:
  - Added python3 to all target
  - python3 → make -f Python3.mk python3
