- Claude launched in-OS (per fry1640, end-to-end shell+keyboard works) but on a real prompt:
  "error connection refused" -> "...may not be available in this country" -> exited.
- Zack: this worked fine before (fry1583, June 16), no code change, and it is NOT a country issue.

DIAGNOSIS (evidence, host-side, all read-only)
- Host egress is US on BOTH stacks (Verizon, ipinfo + Cloudflare cdn-cgi/trace loc=US). No VPN, no
  Tailscale exit node, no wg/tun iface. So traffic is NOT tunneled abroad. The "country" line is a RED HERRING.
- api.anthropic.com returns a clean 401 from this egress over IPv4 AND IPv6 (healthy "no auth key" response,
  NOT a 403 country block). The raw API is reachable and does not geo-block this IP.
- OAuth token (claudeAiOauth, Pro) is VALID 6+ hours; TaterTOS reuses the host's ~/.claude/.credentials.json.
  So auth/token is NOT the problem. The host's own Claude Code works fine concurrently.
- ROOT CAUSE: host /etc/resolv.conf is now "generated by tailscale" -> nameserver 100.100.100.100 (MagicDNS).
  QEMU user-net (slirp) hands the guest DNS 10.0.2.3 (slirp's proxy), which forwards to the HOST resolv.conf
  = 100.100.100.100. slirp's userspace NAT cannot route to the Tailscale CGNAT resolver -> guest DNS silently
  dies -> Claude/Bun can't resolve api.anthropic.com -> connect fails -> Claude prints its CANNED fallback
  "may not be available in your country". Confirms fry1640's DNS-egress note as the real and only blocker.
- WHY IT WORKED BEFORE: the image ships NO /etc/resolv.conf, so glibc/Bun fell back to the DHCP resolver
  (10.0.2.3). In June the host resolv.conf pointed at a reachable router/ISP resolver, so 10.0.2.3 worked.
  Tailscale later took over host DNS (100.100.100.100), which slirp can't reach -> the same fallback now fails.

CONSTRAINT (Zack, hard): do NOT touch Tailscale. `tailscale set --accept-dns=false` was REJECTED — it changes
host-wide DNS and risks breaking his website/API service resolution. Fix had to be guest-side only.

VERIFIED THE FIX TARGET IS REACHABLE (read-only)
