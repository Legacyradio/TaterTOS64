CONCLUSIONS:
  1. Codex's posix.c opendir/readdir/closedir adapter is a CORRECT FIX, not the
     bug. Header layout (fry_readdir_ex_hdr) matches kernel fry_dirent_hdr
     exactly (16B: rec_len/name_len/attr/size). readdir() loop always advances
     by rec_len>=sizeof(hdr) with an EIO guard -> no infinite loop. DO NOT
     revert it.
  2. The freeze is a NEW, LATER hang: CPython now imports encodings fine and
     proceeds into post-encodings startup (stdio stream init via _io, then
     `site`) before tatertos_bootstrap.py prints its first "PYTHON ENVIRONMENT"
     header. The hang is in a kernel syscall that does not return.
  3. The directory adapter does ONE-SHOT readdir into a fixed 128KiB buffer;
     kernel readdir_ex_cb silently truncates when full (returns 1). Not a hang,
     but a latent correctness bug for large dirs (site-packages) — note for
     later, not the current blocker.
