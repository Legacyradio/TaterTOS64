ROOT CAUSE (diagnosed): _PyThreadState_Attach reads the current tstate from TLS;
on a newly-spawned thread it must be NULL, but it returns the MAIN thread's
tstate. => pthread_create on TaterTOS does NOT give each new thread its own TLS
block / %fs base, so `__thread` vars (incl. CPython's current-tstate
`_Py_tss_tstate`/current_fast) are SHARED across threads. The first thread the
async agent / _asyncio spawns collides with the main thread's state. The
fry1701-1706 ELF-TLS work set up variant-II TLS for the MAIN thread only; spawned
threads need the same (own TLS image + TCB + user_fs_base).
