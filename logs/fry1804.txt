=== EXPERIMENT 2 — is the NameError a masking artifact? YES ===
Hypothesis: if a submodule is already in sys.modules when asyncio/__init__ runs,
`from .base_events import *` is served from sys.modules and SKIPS
_find_and_load_unlocked(), which is the only place that does
setattr(parent_module, child, module). Line 26's bare name then cannot resolve.
IN-OS TEST (space-free):
  python3 -c sys=__import__("sys");sys.modules["asyncio.base_events"]=__import__("types").ModuleType("asyncio.base_events");__import__("asyncio")
  -> REPRODUCED the exact "NameError: name 'base_events' is not defined"
     (serial :3751-3758).
HOST CONTROL — the decisive one:
  host CPython 3.14.6 (/usr/lib/python3.14), same test -> FAILS IDENTICALLY.
=> This is STANDARD CPYTHON BEHAVIOUR on any platform. NOT a TaterTOS bug.
   The NameError is what you get on the SECOND import attempt after a FIRST
   attempt failed partway: CPython removes sys.modules['asyncio'] on failure but
   LEAVES the submodules it already loaded. The retry re-runs __init__ and dies
   on the stale-submodule NameError, HIDING the original error.

=== ROOT CAUSE (exact) ===
asyncio/selector_events.py:33-39 (upstream, unmodified):
    _HAS_SENDMSG = hasattr(socket.socket, 'sendmsg')
    if _HAS_SENDMSG:
        try:
            SC_IOV_MAX = os.sysconf('SC_IOV_MAX')
        except OSError:              # <-- catches OSError ONLY
            _HAS_SENDMSG = False
Upstream DOES guard this call — but only against OSError. CPython's
posix_sysconf raises **ValueError("unrecognized configuration name")** when the
name is absent from os.sysconf_names, and ValueError sails straight through the
handler and aborts the import.

WHY THE NAME IS ABSENT: src/include/unistd.h defines _SC_CLK_TCK, _SC_OPEN_MAX,
_SC_PAGESIZE, _SC_NPROCESSORS_ONLN/CONF, _SC_PHYS_PAGES, _SC_AVPHYS_PAGES,
_SC_LINE_MAX, _SC_HOST_NAME_MAX, _SC_TTY_NAME_MAX, _SC_GETPW_R_SIZE_MAX —
but NOT _SC_IOV_MAX. CPython's posixmodule.c builds its sysconf_names table from
`#ifdef _SC_*` guards, so an undefined macro means the key does not exist at all.
Confirmed shape of the message matches CPython's undefined-name path exactly.
Also note src/user/libc/posix.c:598 sysconf() only handles _SC_CLK_TCK,
_SC_PAGESIZE and _SC_NPROCESSORS_ONLN, returning -1 for everything else.

=== PROPOSED FIX (fry1805 — NOT approved, awaiting Zack) ===
Do it properly in the OS, not by patching stdlib:
  1. src/include/unistd.h: `#define _SC_IOV_MAX 60`   (the Linux value)
  2. src/user/libc/posix.c:598 sysconf(): `if (name == _SC_IOV_MAX) return 1024;`
     (Linux IOV_MAX is 1024; asyncio uses it to cap sendmsg iovec batches)
Rejected alternative: editing asyncio/selector_events.py to catch ValueError.
That is patching the stdlib to hide an OS gap — wrong layer, and it would have
to be re-applied on every Python upgrade.
