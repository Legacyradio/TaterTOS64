=== WHY (the defect) ===
  src/user/libc/gap_stubs.c:98  (BEFORE)
      int ftruncate(int fd, off_t l) { (void)fd;(void)l; return 0; }
  src/user/libc/gap_stubs.c:105 (BEFORE)
      int truncate(const char *p, off_t l) { (void)p;(void)l; return 0; }
Both did nothing and returned 0. They did not fail — they REPORTED SUCCESS.
That is the most dangerous shape a stub can take, because no caller ever finds
out. Contrast lockf() on the adjacent line, which honestly sets ENOSYS and
returns -1; that is the correct shape for a genuine gap.
CONSEQUENCE ON RECORD: SQLite calls ftruncate to size the database file and to
truncate journals. /.hermes/state.db has been 0 bytes on the image since
2026-08-11 across every run (logs/fry1812.txt FINDING 2).

=== CHANGES ===
1. src/user/libc/posix.c — added directly after lseek(), before fcntl():
     int ftruncate(int fd, off_t length)
       rejects length < 0 with EINVAL, else
       posix_error_int(fry_ftruncate(fd, (uint64_t)length)) — the same idiom as
       every other wrapper in this file (open/close/fcntl/poll, posix.c:98-138).
     int truncate(const char *path, off_t length)
       there is NO path-based truncate syscall in the native ABI, so this does
       what a libc without one does: open(path, O_WRONLY) -> ftruncate -> close.
       The errno from ftruncate is saved across close() so the caller sees the
       real failure rather than whatever close() last set. NULL path and
       negative length rejected with EINVAL.
   No new header needed: fcntl.h (O_WRONLY) and unistd.h are already included
   at posix.c:36-38, and both prototypes already exist at unistd.h:94-95.
2. src/user/libc/gap_stubs.c:98 and :105 — both stubs DELETED, each replaced
   with a comment saying what it did, why it was dangerous, where the real
   implementation now lives, and not to reinstate it. Deletion is required, not
   optional: two definitions would be a duplicate symbol at link time.
