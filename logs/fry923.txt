TaterTOS64 changes:
  src/include/fcntl.h
    - Added O_NDELAY as an alias for O_NONBLOCK.
    - Added F_RDLCK, F_WRLCK, F_UNLCK.
    - Added POSIX struct flock.

  src/include/unistd.h
    - Added pwrite declaration.
    - Added ftruncate64 declaration as the 64-bit alias surface for ftruncate.

  src/include/sys/time.h
    - Added utimes and futimes declarations.

  src/include/pthread.h
    - Extended pthread_mutexattr_t with protocol storage.
    - Added PTHREAD_PRIO_NONE, PTHREAD_PRIO_INHERIT, PTHREAD_PRIO_PROTECT.
    - Added pthread_mutexattr_getprotocol / setprotocol declarations.
    - Added pthread_condattr_getclock / setclock declarations.

  src/user/libc/posix.c
    - Implemented pread and pwrite as offset-preserving wrappers using the
      existing fry_lseek + fry_read/fry_write ABI.
    - Implemented ftruncate using existing fry_ftruncate.
    - Implemented ftruncate64 as an alias to ftruncate.
    - Implemented truncate via open + ftruncate + close.
    - Implemented utimes via utimensat conversion.
    - Implemented futimes as fd validation plus timestamp no-op matching the
      current timestamp-storage limits of the filesystem layer.

  src/user/libc/pthread.c
    - Initialized mutex protocol attrs to PTHREAD_PRIO_NONE.
    - Implemented pthread_mutexattr_getprotocol / setprotocol.
    - Initialized cond clock attrs to CLOCK_REALTIME.
    - Implemented pthread_condattr_getclock / setclock.

Why:
  Chromium base/files and base/synchronization POSIX code required these normal
  POSIX declarations/constants to compile. The TaterTOS ABI already had
  ftruncate and seek/read/write primitives, so the libc surface could be
  completed without adding Linux code or pretending a syscall exists.

Chromium changes:
  base/threading/platform_thread_posix.cc
    - Changed pthread_self() conversion to cast through uintptr_t and then to
      PlatformThreadId::UnderlyingType.
    - The first suggested int64_t cast was wrong for this target because
      PlatformThreadId::UnderlyingType is pid_t on POSIX, and pid_t is int.

  base/parameter_pack.h
    - Replaced local constexpr any_of/all_of helpers using
      std::ranges::contains(initializer_list<bool>, ...) with explicit
      constexpr loops.
    - Reason: GCC + Chromium libc++ hit a constexpr failure inside
      libc++ __constexpr_memchr while evaluating Chromium trait packs. This is
      a compiler/libc++ constexpr fast-path issue, not a TaterTOS POSIX header
      issue. The local loop preserves semantics and avoids the bad fast path.
